本节从“本地 HTML 文件”过渡到“互联网上的网站”，讲清楚浏览器访问网页时背后的基本链路：先通过 DNS 找到域名对应的 IP，再根据 HTTP/HTTPS 访问默认端口 80/443，最后把服务器返回的 HTML 渲染成页面。

<!--more-->

## 核心理解

本地 HTML 文件只是电脑上的一个文件。它可以被浏览器打开，也可以被渲染成页面，但它还不是一个真正意义上的网站。

当这些 HTML、CSS、JavaScript、图片等资源被放到一台持续联网、能够对外提供访问的服务器上，其他人可以通过浏览器访问它时，它才成为网站。

所以，网站并不是一个神秘的东西。它本质上是放在服务器上的资源集合，浏览器通过网络把这些资源请求回来，再渲染成我们看到的页面。

## 访问网站的完整流程

当你在浏览器里输入一个网址时，浏览器背后大致会经历这样一条链路：

1. 输入网址。
2. 浏览器通过 DNS 查询域名对应的 IP 地址。
3. 浏览器根据 IP 地址找到目标服务器。
4. 浏览器连接服务器上对应的端口。
5. 服务器返回 HTML 等网页资源。
6. 浏览器解析并渲染这些内容，最终显示成网页。

可以把它理解成：

```text
网址 -> DNS -> IP 地址 -> 端口 -> 服务器资源 -> HTML -> 浏览器渲染
```

## DNS：互联网里的通讯录

浏览器并不会直接通过“域名”找到一台服务器。域名更像是方便人类记忆的名字，比如：

```text
example.com
```

但计算机真正需要的是 IP 地址。DNS 的作用，就是维护“域名 - IP 地址”的对应关系。

你输入域名后，浏览器会先去查询 DNS，找到这个域名背后对应的服务器 IP。这个过程有点像查通讯录：你记住的是名字，通讯录帮你找到电话号码。

## IP 和端口分别解决什么问题

IP 地址解决的是“去哪一台机器”的问题。

端口解决的是“访问这台机器上的哪个服务”的问题。

一台服务器上可能同时运行很多服务，比如网站服务、数据库服务、后台接口服务等。只有 IP 地址还不够，还需要端口来定位具体入口。

常见的网页访问协议有两个默认端口：

| 协议 | 默认端口 | 说明 |
| --- | --- | --- |
| HTTP | 80 | 普通网页传输协议 |
| HTTPS | 443 | 更安全的网页传输协议 |

所以我们平时访问网站时通常不用手写端口。比如：

```text
https://example.com
```

浏览器会默认按 HTTPS 的 443 端口处理。

## 本地文件和网站的区别

本地 HTML 文件：

- 文件只放在自己的电脑上。
- 可以用浏览器打开。
- 通常只能自己访问。
- 地址一般是本地文件路径。

网站：

- 文件放在服务器上。
- 服务器持续联网并对外提供访问。
- 其他人可以通过域名或 IP 访问。
- 浏览器通过 HTTP/HTTPS 请求资源。

这就是“本地页面”和“互联网网站”的关键差别。

## 思考

**为什么输入一个网址就能打开网页？**

因为浏览器会先通过 DNS 找到域名对应的 IP，再连接到服务器上对应的端口，请求网页资源，最后把返回的 HTML 渲染出来。

**IP 地址和端口分别解决什么问题？**

IP 用来找到“哪一台机器”，端口用来找到“这台机器上的哪个服务”。两者一起才能准确访问目标网站。

**为什么 HTTP 和 HTTPS 常常不用手写端口号？**

因为它们有默认端口。HTTP 默认是 80，HTTPS 默认是 443。浏览器会按默认规则处理，所以通常可以省略。

**本地 HTML 文件和网站有什么本质区别？**

本地 HTML 只是电脑上的一个文件；网站则是把内容放在服务器上，外部用户可以通过网络访问。

## 术语解释

- **HTML**：超文本标记语言，网页内容的基本文件格式。
- **网站**：放在服务器上、可以通过网络访问的网页或资源集合。
- **服务器**：一台持续对外提供资源和服务的电脑。
- **IP 地址**：互联网中用于定位一台机器的地址。
- **DNS**：域名系统，负责把域名转换成对应的 IP 地址。
- **端口**：机器上用于区分不同服务的入口编号。
- **HTTP**：网页传输协议，浏览器和服务器之间通信时常用。
- **HTTPS**：更安全的网页传输协议，默认使用 443 端口。
